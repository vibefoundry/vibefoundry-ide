# geo_dashboard

Track 2 PWA — **Distribution Geo Dashboard** boilerplate. Vite-built variant (the project's only Vite-based Track 2 app — see project AGENTS.md for why plain-script is the default).

## What this is

A generic interactive geo dashboard for any "accounts × products × multi-period sales" dataset: filterable table + map, county heatmap, and state/county/tract boundary overlays. Runs entirely in the user's browser via DuckDB-WASM querying a Parquet file.

The default sample data ships an olive-oil distributor in the US Northeast (NY, NJ, MA, PA, CT, RI). Swap `sample_data/sample.parquet` (or drop a real parquet at `input_folder/app_data.parquet`) to use it for a different business.

## Genericization status

This app is at **Option A** of the A→B→C generic plan:

- **A (current)**: Top-of-file constants externalized to `public/data/app_config.json`. Inline column references in `js/app.js` still hardcoded. Same shape, same behavior — only the config schema is portable.
- **B (future)**: Replace inline domain labels (BATFS, Brand Variant, Visitation Priority) with config-driven display names so a different business can reuse the app via config swap.
- **C (future)**: Schema-agnostic engine — every inline column reference becomes a role lookup from config.

The forward-compatible `app_config.json` schema already includes fields (`role`, `label`, `filterable`, `color_map`) that are inert under A and ready for B/C to consume.

## Data sourcing (build script priority)

`build_app_package.py` resolves the dataset in this order:
1. `input_folder/{file_from_app_config.json}` — real client data
2. `sample_data/sample.parquet` — synthetic fallback (small, committed)
3. Existing `public/data/{file}` if present (no-op)

The build script prints a banner indicating which source it used.

## Two dev workflows

| Goal | Command | What it does |
|---|---|---|
| Production-shaped local run | `bash run_app.sh` | Runs `build_app_package.py` → spins up the actual distributable in `output_folder/` |
| Fast HMR iteration on `js/app.js` | `bash start_dev.sh` | Starts `vite dev` on localhost:5173 with hot reload |
